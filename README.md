# Karaoke Studio

Сайт создаёт полное вертикальное караоке-видео MP4 1080×1920 из названия песни и имени исполнителя. Поиск оригинала — YouTube, текст — LRCLIB, минус — нейросеть HTDemucs, видео — FFmpeg. Пользовательский музыкальный API-ключ не нужен. Есть отдельный ручной редактор с загрузкой файлов и LRC.

## Сайт на GitHub Pages

Адрес: https://glebustinoff-ctrl.github.io/GUcodex/

GitHub Pages размещает интерфейс. Обработку выполняет `.github/workflows/karaoke.yml` в GitHub Actions:

1. Владелец репозитория вводит название и исполнителя на сайте и нажимает «Создать караоке автоматически».
2. Открывается заранее заполненная публичная задача GitHub. Нужно войти в свой аккаунт и нажать Create / Submit new issue. Если браузер заблокировал вкладку, ссылка остаётся на сайте.
3. Workflow принимает только задачи от владельца репозитория. Он ищет запись, получает текст, отделяет вокал и собирает всё видео. Подготовка модели и обработка могут занять несколько минут или дольше.
4. Сайт проверяет статус через публичный GitHub API. Результат доступен на сайте и в комментарии к задаче: MP4, MP3-минус, LRC или TXT. Файлы публикуются в GitHub Release `karaoke-<номер задачи>` и доступны публично.

Токены в браузер не передаются. Workflow использует автоматический `GITHUB_TOKEN` с правами на результаты этого репозитория. Пользователь не вводит API-ключи. Публичные посетители, не являющиеся владельцем, не могут запускать обработку. Новые задачи ожидают свободного обработчика; GitHub может ограничивать доступность Actions. Публичные задачи и релизы нужно учитывать при выборе материала для публикации. Если закрыть вкладку сайта, результат останется в задаче GitHub. «Прекратить ожидание» останавливает проверку статуса в браузере, а уже отправленная задача продолжает работу.

Для проверки обработчика во вкладке Actions → Create karaoke video предусмотрены `workflow_dispatch` режимы: `source-check` проверяет получение настоящего аудиофайла без публикации; `selftest` запускает настоящую нейросеть на собственном синтетическом сигнале и создаёт 8-секундный MP4; `end-to-end` проходит весь путь от поиска песни до полного видео. Результаты последних двух режимов хранятся во временном artifact три дня. Эти режимы не создают задачи или релизы.

## Доступность источников и качество

Поиск работает через `yt-dlp`, без cookies, входа в YouTube и обхода защиты. Адаптер проверяет название и исполнителя, отклоняет неподходящие каверы, ремиксы, трансляции и короткие фрагменты, предпочитает официальные аудиозаписи. Это снижает риск неверного выбора, но не гарантирует одинаковую студийную версию во всех каталогах. YouTube может запросить вход, ограничить регион или заблокировать IP обработчика. При недоступности записи задача завершается явной ошибкой. Успешная установка загрузчика не доказывает доступность конкретной песни.

Текст берётся из LRCLIB, без ключа. Для LRC требуется совпадение названия и исполнителя и длительность с разницей не более 6 секунд. При наличии только обычного текста строки распределяются равномерно с предупреждением; точного выравнивания по вокалу нет. Подсветка слов внутри строки приблизительная. Если текста нет, автоматическая обработка останавливается.

HTDemucs делает минус из оригинала. Вокал и инструменты могут разделяться с артефактами; полное удаление голоса не гарантируется. Проверенная официальная модель загружена; реальное нейросетевое разделение и MP4 проверены на собственном 8-секундном сигнале. Это не измерение качества на вокальной записи. В текущей облачной среде прямой доступ к YouTube отклоняется сетевым прокси (CONNECT 403). Отдельная проверка настоящей загрузки и чтения аудио в GitHub Actions завершилась успешно: [source-check](https://github.com/glebustinoff-ctrl/GUcodex/actions/runs/39057066968). Это не гарантия доступности всех песен.

## Серверная версия

Нужны Node.js 22+ (проверено на 24), Python 3.10+, FFmpeg/FFprobe с libass, libx264, AAC, MP3 и шрифтом DejaVu Sans. Npm-зависимостей нет. В Debian/Ubuntu системные пакеты: `ffmpeg fonts-dejavu-core python3-venv`.

```sh
cd /workspace/GUcodex
npm run setup:ai
npm start
```

Скрипт установки использует CPU Torch/Torchaudio 2.5.1, Demucs 4.0.1, yt-dlp с JavaScript-компонентом и получает HTDemucs с официального `dl.fbaipublicfiles.com`. TLS и контрольная сумма модели включены; ожидаемый префикс SHA-256 — `8726e21a`. Зависимости и веса хранятся в игнорируемых `.venv/` и `.models/`. Установка повторно использует кэш. Нельзя подменять readiness-файл или отключать проверку сертификатов/хеша. Dockerfile подготовлен для отдельного Linux-сервера; его сборка здесь не проверялась.

Порт по умолчанию — 3000, меняется через `PORT`. Проверка: `GET /api/health` и `/api/auto/status`. `POST /api/auto` принимает `{ "title": "Название", "artist": "Исполнитель", "theme": "violet" }`, `GET /api/auto/jobs/:id` возвращает статус. Завершённые задания сохраняются в `.data/<id>/result.json` и восстанавливаются после перезапуска. Медиа не удаляются автоматически. Не удаляйте `.data/` с пользовательскими файлами. Локальный сервер однопользовательский, без аутентификации; для открытого размещения нужны ограничения доступа и хранения.

Отдельный сервер можно подключить к Pages переменной сборки `KARAOKE_API_URL`: HTTPS-origin без пути и параметров. Тогда сайт использует его вместо GitHub Actions и не открывает задачу. На сервере CORS по умолчанию разрешает `https://glebustinoff-ctrl.github.io`; `CORS_ORIGIN` меняет origin. Вспомогательный VK-адаптер оставлен для ручного редактора и скрыт без `VK_AUDIO_ACCESS_TOKEN`; основному режиму этот токен не нужен. Реальная интеграция VK не проверена.

## Ручной редактор и сборка

```sh
npm test
npm run build:pages
```

Тесты проверяют реальный FFmpeg MP4, полный трек, тайминг, загрузку и range-запросы, поведение источников и передачу задач GitHub. Тест автоматического API использует тестовый источник и подставной разделитель; он не заменяет настоящую сетевую проверку и нейросетевой прогон.

В статической версии ручные аудиофайлы хранятся в IndexedDB браузера. Работают демо, загрузка файлов, LRC, предпросмотр, проекты и запись всего видео через Canvas/Web Audio/MediaRecorder. Формат — MP4, если поддерживается браузером, иначе WebM. Запись идёт в реальном времени, вкладку нужно держать активной. Экспериментальное вычитание стереоканалов в ручном редакторе отличается от HTDemucs и может убирать центральные инструменты.

Сборка `dist/` содержит только интерфейс и фоновые изображения: без медиа, моделей и секретов. Пути относительные и поддерживают `/GUcodex/`. Публикация использует ветку `gh-pages`, Pages → Deploy from a branch → gh-pages → / (root). Дополнительный `.github/workflows/pages.yml` для main отклоняется существующей защитой окружения github-pages, разрешающей только gh-pages; текущая публикация работает через стандартный Pages workflow этой ветки. Успешный push не заменяет проверку deployment и публичного HTTPS.

В облачных задачах используйте существующий checkout `/workspace/GUcodex`. Отдельный worktree не нужен без явного запроса пользователя. Процесс сервера нужно запускать заново после создания новой машины. Сохранённые настройки среды и публикация сайта — отдельные операции.

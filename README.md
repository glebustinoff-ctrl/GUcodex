# Karaoke Studio

Сайт для создания полного вертикального караоке-видео: текст песни, аудио, синхронизация, оформление и скачивание MP4 1080×1920, 30 fps.

## Сайт на GitHub Pages

Предусмотрены два режима: серверная версия ниже и автономная версия для GitHub Pages. Статическая сборка создаётся командой `npm run build:pages` в `dist/`; зависимости npm не нужны. Все ссылки относительные, поэтому сайт работает и в подпапке `/GUcodex/`.

На GitHub Pages аудио хранится в IndexedDB браузера. Работают загрузка файлов, демо, LRC, предпросмотр, сохранение проектов и запись всего видео 1080×1920 через Canvas + Web Audio + MediaRecorder. Формат выбирается по возможностям браузера: MP4, если поддерживается, иначе WebM. Запись идёт в реальном времени; вкладку нужно держать открытой и активной. Браузерный поиск текстов обращается к LRCLIB напрямую и зависит от доступности источника и его CORS. Ключей в статической сборке нет.

**VK-поиск и импорт требуют серверной версии с отдельным аудиодоступом VK.** GitHub Pages не выполняет Node.js и FFmpeg. Статическая версия сообщает это явно и предлагает загрузку своих аудиофайлов. Из-за нагрузки возможности экспорта зависят от устройства и браузера.

Workflow `.github/workflows/pages.yml` публикует `dist/` после отправки ветки `main`. Если Pages ещё не включён, в репозитории откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**, затем запустите **Actions → Deploy Karaoke Studio to GitHub Pages → Run workflow**. Это настройка репозитория, отличная от публикации облачной среды Codex. Публичный адрес считается подтверждённым только после успешного deployment и проверки HTTP.

Можно опубликовать готовую статическую сборку отдельной веткой `gh-pages`; для неё источник Pages — **Deploy from a branch → gh-pages → / (root)**. Не включайте одновременно две схемы публикации. Ни `.data/`, ни секреты сервера в сборку не копируются.

## Запуск

Нужны Node.js 22+ (проверено на 24) и FFmpeg/FFprobe с `libass`, `libx264`, AAC и шрифтом DejaVu Sans. В подготовленной облачной среде всё установлено. Для Debian/Ubuntu: `sudo apt-get install ffmpeg fonts-dejavu-core`.

```sh
cd /workspace/GUcodex
npm start
```

Сервер слушает порт 3000; переменная `PORT` меняет порт. Для разработки: `npm run dev`. У приложения нет сторонних npm-зависимостей и шага сборки.

```sh
npm test
```

Тесты проверяют LRC, смещения, генерацию субтитров и фона, поиск через тестовый источник, загрузку настоящего WAV, воспроизведение с Range, создание реального MP4, размер кадра, аудиопоток, длину и смену кадров караоке. Внешний LRCLIB проверяется отдельно, тестовый источник не доказывает его сетевую доступность.

## Как пользоваться

1. Ввести название и исполнителя. Поиск в LRCLIB возвращает текст и, если есть, LRC с временем строк. При недоступности источника можно вставить текст или загрузить LRC/TXT.
2. Выбрать найденную в VK запись при подключённом API или загрузить минус и/или плюс (MP3, WAV, M4A, FLAC, OGG, до 100 МБ, до 20 минут). Выбрать звуковую дорожку для видео.
3. Проверить текст в плеере. Без LRC строки распределяются равномерно по треку; кнопка «Расставить таймкоды» делает их редактируемыми. Положительный сдвиг задерживает текст. Подсветка слов внутри строки приблизительная, по длине слов.
4. Выбрать тему и размер текста, нажать «Создать караоке». Сервер обрабатывает **всю** песню и выдаёт ссылку на MP4. Во время экспорта плеер останавливается.
5. Проект можно сохранить в localStorage этого браузера и открыть через «Мои проекты». Аудио остаётся на сервере, в проекте сохраняются только идентификаторы файлов.

Кнопка «Попробовать демо» создаёт 32-секундный синтезированный аккорд с собственным демонстрационным текстом. Это не запись известной песни и не демонстрация распознавания вокала.

## Что реализовано и что требует отдельной интеграции

- **Поиск:** настоящий HTTP-запрос к `https://lrclib.net/api/search`; ключ не требуется. Сетевой политике облачной среды нужен домен `lrclib.net`. Если он заблокирован, сайт показывает ошибку и предлагает ручной ввод.
- **Плюс и минус из VK:** реализован условный API-адаптер `audio.search` / `audio.getById`. **Работа с настоящим VK пока не подтверждена:** в текущей среде отсутствует аудиотокен и сетевые запросы к VK блокируются политикой. Проверены контракт адаптера на тестовых ответах, обработка отказов, защита URL загрузки и отсутствие передачи токена на CDN. Это не подтверждение доступности аудиометодов для обычного приложения VK.
- **Приглушение вокала:** экспериментальное вычитание каналов стереозаписи. Это не нейросетевое разделение: может убрать центральные инструменты, бас и часть музыки, вокал может остаться. На монофайлах отключено. В предпросмотре играет оригинал, эффект применяется при экспорте. Для качественного минуса нужен готовый файл или отдельный сервис разделения дорожек.
- **Тайминги:** LRC по строкам или приблизительное равномерное распределение. Автоматического распознавания и точного выравнивания слов по вокалу нет.
- **Предпросмотр:** показывает тот же фон, тему и тайминг, но браузер и libass могут немного различаться в переносах и шрифтовом рендеринге. Декоративная волна и элементы плеера в MP4 не включаются.

## Подключение VK Музыки

Выбранный пользователем источник — https://music.vk.com/. Поиск текста в LRCLIB и поиск аудио в VK запускаются вместе; результаты независимы. Поиск оригинала и поиск по запросу «минус» выполняются отдельно. Найденное по слову «минус» не обязательно является инструменталом: версию нужно прослушать.

Для проверки интеграции нужен `VK_AUDIO_ACCESS_TOKEN` приложения, которому VK разрешил аудиометоды. В облачной среде значение вводится **в секретах настроек среды**, с целевым HTTPS-доменом `api.vk.com`. Не присылайте пароль, cookies или токен в чат; не коммитьте их в репозиторий. В обычном локальном запуске используется одноимённая переменная процесса. Её значение не передаётся в браузер, в логи или на аудио CDN.

Подписка VK Музыки сама по себе не подтверждает доступ к аудио API. Обычный токен может получить отказ. Если VK не предоставляет вашему приложению эти методы или полный URL записи, адаптер покажет причину; нужно получить соответствующий доступ у VK либо использовать загрузку файлов. Отсутствие токена, отказ API, HLS вместо файла и неподдерживаемый аудиодомен обрабатываются как ошибки. Обход авторизации и защиты не реализован.

В сетевых настройках подготовлен доступ к `api.vk.com`, `music.vk.com`, `vk.com`, `dev.vk.com`, `*.vkuseraudio.net`, `*.userapi.com`, а также `lrclib.net`. Сохранение черновика не доказывает применения этих правил к текущему процессу. После применения настроек нужно повторить настоящий поиск и импорт. Импорт принимает только HTTPS-файлы поддерживаемых CDN VK; каждый редирект проверяется заново. После получения реального ответа может понадобиться уточнить список CDN или обновить версию/контракт API.

## Хранение и эксплуатация

Это рабочая **однопользовательская локальная версия**, не публичный многопользовательский сервис. Сервер доступен на `0.0.0.0` для облачного окружения; аутентификации нет. Не выставляйте его в открытый интернет без ограничения доступа. Для публичного запуска нужны авторизация, изоляция файлов пользователей, квоты, очередь задач и управление правами на музыку.

Файлы находятся в игнорируемой Git папке `.data/`: аудио, метаданные и готовые видео. Они не удаляются автоматически. Удаление `.data/` удаляет медиа и нарушает ссылки старых проектов. Статус выполняющихся задач хранится в памяти; после перезапуска сервера незавершённый экспорт нужно запустить заново. Один процесс экспортирует одно видео одновременно, FFmpeg использует два потока. Длинные видео могут занимать значительное время и место.

В облачных задачах используйте существующий checkout `/workspace/GUcodex`. Отдельный Git worktree не нужен, если пользователь не попросил его явно. Запущенный сервер не переживает создание новой машины: повторите `npm start` и проверьте `/api/health`.
